# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Brand vs. internals

User-facing brand is **EclipVPN**. As of release **2026.06** the internals were renamed `flowvpn` → `eclipvpn` as well: CLI `/usr/bin/eclipvpn`, libs `/usr/lib/eclipvpn/`, config `/etc/eclipvpn/`, runtime tmp `/tmp/eclipvpn/`, service `/etc/init.d/eclipvpn`, CGI `/www/cgi-bin/eclipvpn`, nft tables `eclipvpn`/`eclipvpn_dns`, logger tag `eclipvpn`, shell vars `$ECLIPVPN_*`, and the version constant `ECLIPVPN_VERSION` in `usr/bin/eclipvpn`.

Two things deliberately **stay `flowvpn`** — do not rename them:
- The **GitHub repo** `1eningrad/flowvpn` (the `install.sh` raw-URL and the UI footer links point at it; renaming the URL 404s the installer). Rename the repo on GitHub first if you want these to change.
- The **legacy `/www/flowvpn/` → `/eclipvpn/` redirect** stub (created by the installers) for old bookmarks.

`install.sh` / `install-from-mac.sh` / `deploy.sh` carry a one-time, idempotent **migration**: on a router with an old `flowvpn` install they stop+disable the old service, kill its watchdog (matched by the start-anchored cmdline `"/bin/ash /usr/bin/flowvpn watchdog"*`), clean its nft tables + dnsmasq drop-in, `mv /etc/flowvpn /etc/eclipvpn` (preserving subscription/settings), and remove the old files.

## What this is

A VPN manager for OpenWrt routers. Written almost entirely in **busybox ash** (`#!/bin/ash`, not bash) with a single-file HTML/JS web UI. Two binaries do the actual work: **xray** (SOCKS outbound, VLESS+XHTTP over either **Reality** *or* plain **TLS**) and **sing-box** (tproxy inbound, DNS, routing). Everything else is glue. The TLS variant is what powers **CDN fronting** — `xray.sh` switches on the subscription entry's `security` field (`reality` → `realitySettings`, `tls` → `tlsSettings`), so a server can front through a CDN (`sni=*.selcdn.net`) to dodge the per-flow policer (see "CDN fronting" below).

There is no build step and no package manager for the router code — it is shipped to a live router as-is via `deploy.sh` (CI does exist: syntax + manifest + unit checks, see "Testing"). (The Windows installer under `windows-installer/` is the one piece with a build step — see its section below.) There **is** a unit-test suite (`tests/`, added 2026-06-16) covering the pure parsers, input validators, and the lock / config-write primitives — see "Testing" below.

### Testing

`tests/run.sh` is a small ash+jq unit suite (added 2026-06-16) — the first automated net for ~7k lines of shell. It sources the REAL code (`usr/bin/eclipvpn` with `ECLIPVPN_SOURCE_ONLY=1`, which stops before init/the dispatch case) against a scratch `ECLIPVPN_TMP`/`ECLIPVPN_CONFIG`, so tests call the actual functions — no copies. The three path vars (`ECLIPVPN_LIB`/`ECLIPVPN_CONFIG`/`ECLIPVPN_TMP`) are overridable for exactly this reason; production passes none, so defaults are unchanged. Suites: `test_parse.sh` (proxy-URL + subscription-body parsers, `url_decode`, `_b64_pad`), `test_validators.sh` (`_validate_ipv4`, `_normalize_mac`, engine helpers, `_is_metered_server`, the `muted_servers` matcher `_name_has_token`/`_is_auto_skipped` + a `mute-server`/`unmute-server` round-trip), `test_locks.sh` (`_op_begin` TOCTOU + `_config_lock`), `test_config.sh` (`update_config` RMW, concurrency, backup rotation), `test_switch.sh` (make-before-break port arithmetic — `_stage_xray_port`/`_active_xray_port`), `test_state.sh` (the `/etc/eclipvpn/state/` journal mirror — no-op on a missing/empty source, refill-but-never-clobber, and that `_log_incident`/`_record_switch` actually mirror), `test_dns.sh` (`_dns_direct_list`/`_active_dns_direct`/`_dns_overrides_pairs`, the `set-config` gate for both DNS keys, and the generated `dns` block — shape, override precedence, and byte-stability across config reorderings), `test_subscriptions.sh` (`_merge_sub_pool` — the offline pool rebuild used by `sub enable/disable/remove` — plus the manual single-server subs: `cmd_sub add vless://…`, idempotency, reject-unparseable, http-only `subscription_url` mirror, merge self-heal, remove pruning). ~225 assertions. `run.sh` globs every `test_*.sh`, so a new suite file is picked up automatically (no runner edit needed); pass `switch`/`parse`/etc. to run just one.

Run on the dev box if `jq` is present (`sh tests/run.sh`); the Windows box has no `jq`, so run on the router: `tar c usr tests | ssh root@ROUTER 'rm -rf /tmp/eclvt && mkdir -p /tmp/eclvt && cd /tmp/eclvt && tar x && sh tests/run.sh'`. `tests/` is NOT shipped by `deploy.sh`/installers — it's dev-only. Still verify runtime/UI behaviour with `./deploy.sh` + the UI; the suite covers the pure/lock logic, not the live tunnel. The `test-results/` dir is unrelated (old screenshots). **CI** (`.github/workflows/ci.yml`) runs on every push/PR: `sh -n` + `busybox ash -n` over the `packaging/ship-files` files + dev scripts, the `manifest-guard` (every `usr/lib/eclipvpn/*.sh` must be listed in the manifest), advisory `shellcheck`, and the unit suite via `bash tests/run.sh` — so the suite runs automatically on an Ubuntu runner even though the Windows dev box has no `jq`. **Both the runner and CI enumerate suites by GLOB** (`test_*.sh` / `tests/*.sh`) — a hardcoded list here rotted once: `test_subscriptions.sh` ran but went un-syntax-checked for weeks. Don't reintroduce one.

For UI changes, hard-reload in the browser (`Cmd+Shift+R`) — the CGI sends no-cache headers but the static `index.html` is cached aggressively.

Library scripts are sourced into `usr/bin/eclipvpn` (the `. ## Runtime data flow

```
LAN client → dnsmasq:53 → sing-box DNS:5354 → DoH 1.1.1.1:443 (via VPN) or UDP Yandex 77.88.8.8 (direct)
LAN client → nftables tproxy:2154 → sing-box → xray SOCKS:1080 → VLESS+Reality (VPN)
                                              ↘ direct (RU geosite/geoip + custom direct list)
```

- **mark 0x1** = packet entered tproxy, route via local table 100
- **mark 0x8000** = sing-box/xray's own outbound — anti-loop bypass at the top of `eclipvpn` nft chain
- **DoT (853)** and **QUIC (UDP 443)** are unconditionally rejected so apps fall back to plain DNS / TCP that we control

## Two routing modes

- `all_vpn` — everything → VPN, *except* domains/IPs in `geosite-ru`, `geoip-ru`, and the manual RU list in `rules.sh::_fetch_ru_domains()` (Yandex/VK/Sber/etc).
- `blocklist` — only blocked domains → VPN; everything else direct. Source is `itdoginfo/allow-domains` (curated, ~1.2k) or `1andrevich/Re-filter-lists` (~80k) when `blocklist_source=full`.

**`full_tunnel` (set-config bool, default false)** — in `all_vpn` mode, drops the RU→direct rules entirely (`_build_allvpn_rules` skips the `geosite-ru`/`geoip-ru`/manual-RU → `direct` route rules AND the `geosite-ru`/RU → `dns-direct` DNS rules; `route.final`/`dns.final` are already `default`/`dns-proxy`), so **everything — incl. RU banks — rides the VPN**. This is for networks where the *direct* path can't actually reach RU services: e.g. the router sits behind an upstream that doesn't route major RU subnets (observed 2026-06-20 — Sberbank's `84.252.x` / Yandex-Cloud range was unreachable on the direct path, traceroute dying one hop past the upstream gateway, yet `rc=200` through the VPN exit). With RU-direct on, banks get stranded on the dead direct path; `full_tunnel=true` fixes them. Trade-off: all RU traffic takes the VPN exit (more latency/bandwidth) — only enable it when direct is broken. The force-VPN DNS rule's trailing comma is stripped (`${dns_rules%,}]`) so the DNS array stays valid when the RU rules are skipped. NB: under `full_tunnel` the user's `direct_domains.txt` (→ `ru_rule`) is inert (the whole RU-direct block is skipped).

A **force-VPN list** (`vpn_domains.list`, built-in AI services **+ YouTube** + user's `custom_vpn`) overrides the RU rules in `all_vpn` mode — gemini.google.com / youtube.com etc. would otherwise hit `geosite-ru` (which contains `google.com`). YouTube is in the built-in heredoc (`rules.sh::_fetch_vpn_domains`) so every fresh install routes it through the VPN by default (it's throttled on RU networks); there is also a toggleable `youtube` service preset, but the built-in entry is the always-on baseline.

The **`ru_vpn` preset** (rules.sh) is the surgical alternative to `full_tunnel`: it force-routes specific RU services (YooKassa/YooMoney + Sber/VTB/T-Bank/Alfa websites) through the VPN for uplinks where the direct path can't reach them (the MTS blackhole case), without dragging all RU traffic onto the tunnel. Caveats baked into the preset comment: bank *apps* may still geo-block the foreign exit at login (app-layer, routing can't fix it), and Gazprombank is deliberately absent (403s even via VPN).

## CDN fronting & subscription formats

- **The throttle is a per-flow policer.** The RU-side TSPU pins flows to foreign *hosting* prefixes to ~60-90 KB/s in the evenings, per-TCP-connection (some flows escape), protocol-agnostic (raw TLS shaped the same as VLESS). The watchdog throughput guard (re-dial / switch) only buys minutes against it. The **real** mitigation is **CDN fronting**: the panel serves Selectel-CDN-fronted servers (UI label `🌐 Обход…`, `security=tls`, `sni=*.selcdn.net`) as ordinary subscription entries. They ride a clean CDN prefix the policer doesn't shape. `xray.sh` builds `security=tls` xhttp+tls outbounds for them (not just Reality), so they parse *and* connect like any other server.
- **`_is_metered_server`** (in `usr/bin/eclipvpn`) does NOT count the `Обход` CDN servers as metered, so auto-select / failover may pick them. Because those relays are billed per traffic, the way to stop that is the user's **`muted_servers`** list (`mute-server` / 🔇 in the UI) — see the mute invariants below.
- **`parse.sh` auto-detects the subscription format.** The same URL may return base64-of-proxy-URL-lines (most panels), URL-safe base64, plaintext, *or* a JSON array/object. Detection runs `jq -e 'type=="array" or type=="object"'` on the raw body *before* the base64 cascade — a JSON body must not be fed through `base64 -d` (which would silently corrupt it). **Busybox `tr` gotcha:** the router's busybox does **not** implement the POSIX `[:space:]` class, so `tr -d '[:space:]'` deletes the *literal* characters `[ : s p a c e ]` and corrupts any base64 containing them (it ate the `c` from a Shadowsocks userinfo, 2026-06-15). Strip whitespace by feeding `tr` the actual bytes: `tr -d "$(printf '\n\r\t ')"` (see `_b64_pad`). Do not "simplify" it back to the class form. **`jq` has NO Oniguruma:** OpenWrt/RouteRich jq packages are routinely built without the regex library, so `test()`/`match()`/`sub()` error out (`jq was compiled without ONIGURUMA`). `parse.sh` filters JSON-array proxy strings with `startswith(...)`, NOT `test("^...")` — the regex form silently dropped every entry and made JSON-array subscriptions parse to 0 servers (RouteRich 24.10.5, 2026-06-20). Don't introduce `test`/`match`/`sub` in any jq program; use `startswith`/`contains`/`ascii_downcase` (all regex-free). **`base64` may also be absent** (not in busybox, and the opkg feed is GitHub-hosted → unreachable from RU) — a shim `/usr/bin/base64` over `openssl base64` covers the `base64 -d` calls.
- **Multiple proxy protocols.** `parse.sh` parses `vless://` / `vmess://` (base64-JSON) / `trojan://` / `ss://` (SIP002 + legacy) / `hysteria2://` (+ `hy2://` alias) via a `parse_proxy_url` dispatcher into a uniform server object with a `protocol` discriminator (absent ⇒ `vless`) plus per-protocol credential fields (`hysteria2` uses `password`/`obfs`/`obfs_pw`/`insecure`). `xray.sh::generate_xray_config` branches on `protocol` (vless/vmess/trojan/shadowsocks). The vless branch selects `streamSettings` by `.transport` — `xhttp`/empty, `ws`, `grpc`, or raw `tcp` (the last carries `flow=xtls-rprx-vision` for VLESS-Reality-Vision); Reality stays vless-only. The **`xhttp` sub-branch is kept byte-identical** to the pre-multi-protocol generator so an existing eclip-sub servers.json (all xhttp+reality) regenerates the same `xray.json` (the `cmd_restart` unchanged-config fast path depends on it; verify with a `cmp` of old vs new xray.json for the selected server — proven identical incl. the xmux `extra` merge). The UI shows a small protocol badge (`/status` exposes `protocol`, never credentials). TUIC/WireGuard are still unsupported (parse.sh counts them as unknown and warns).
- **Proxy-engine abstraction (multi-protocol routing).** A server's `protocol` decides which binary dials the exit, via four helpers in `usr/bin/eclipvpn`: `_engine_for_protocol` (→ `"xray"` or `"singbox"`), `_server_protocol IDX`, `_selected_engine`, and `_vpn_running`. vless/vmess/trojan/shadowsocks → **xray** (the shared SOCKS:1080 frontend; sing-box's `default` outbound is socks→xray). **hysteria2 → sing-box NATIVE** (QUIC; xray can't speak it): `singbox.sh::_singbox_proxy_outbound` builds a `type:"hysteria2"` `default` outbound (with `routing_mark:32768` to bypass the tproxy anti-loop), sing-box ALSO opens its own SOCKS:1080 inbound, and a `{"inbound":["socks-in"],"outbound":"default"}` route rule pins that inbound to the tunnel so probes measure it in **both** modes. xray is not launched at all for a hysteria2 server. **`_vpn_running` REPLACES the old bare `is_xray_running && is_singbox_running`** everywhere (lifecycle/servers/domains/config/watchdog/health) — using `is_xray_running` on a hysteria2 server reads "down" forever (xray never runs), which would loop the watchdog reviver and show the VPN as stopped. `lifecycle.sh::_tunnel_bringup` is the shared start path (engine-aware; pre-flights `sing-box version | grep with_quic` for hysteria2). Probe/failover (`cmd_probe_server`, `_watchdog_probe_candidate`) build a throwaway config via `singbox.sh::_gen_probe_config` (echoes the engine; xray ⇒ `run -config`, sing-box ⇒ `run -c`) — a hysteria2 candidate spins up a throwaway sing-box dialer instead of a throwaway xray. Cheap RTT pre-filter (`servers.sh::_reach_ms`) uses ICMP for hysteria2 (UDP — no TCP :443 to connect to); `system-info` exposes `singbox_quic`. **All probe/health paths still curl 127.0.0.1:1080** unchanged — whichever engine is active owns that port.
- **Multiple subscriptions (merge-flat-with-tags).** `config.subscriptions[]` holds N providers `{id,name,url,enabled}` (`id` = md5-8 of the URL ⇒ adding the same URL twice is idempotent). `subscriptions.sh::update_subscription` fetches every *enabled* sub into its OWN cache `sub.<id>.servers.json` (fetch-then-swap PER sub: a blocked/failed panel keeps its last servers), tags each server `sub_id`/`sub_name`, and concatenates them (config order) into ONE flat `servers.json`. Each parsed cache is also MIRRORED to the persistent `/etc/eclipvpn/subcache/` so the last-known pool survives a reboot (see "Files and persistence"); at cold boot `cmd_start` prefers the OFFLINE path (`_restore_subcache` + `_merge_sub_pool`, no network) over a fetch — the tunnel isn't up yet, so a direct fetch to a blocked panel would just burn ~60s of timeouts; the fresh fetch is deferred to the first post-boot `update`. Only a first install (no cache at all → 0-server merge) falls through to the online fetch. **The whole index-based engine is therefore unchanged** — `selected_server` is still a flat index, set-server/auto-select/failover/probe/traffic/incidents all operate on the merged array. `cmd_sub` (subscriptions.sh) is the manager (list/add/remove/enable/disable/rename); `set-config subscription_url` delegates to `cmd_sub add` (back-compat). **enable/disable/remove are instant** — they `_merge_sub_pool` the EXISTING per-sub caches into `servers.json` with NO network fetch and NO rule refresh (only `update`/add re-fetch). A disabled sub's cache is KEPT so re-enabling stays instant (the merge reads enabled subs only); a disabled-while-never-fetched sub triggers one fetch on re-enable. **`_remap_selected_server`** pins the user's selection across a rebuild by IDENTITY (protocol+host+port+name), not raw index — so adding/removing/reordering a sub doesn't silently switch the active server (and fixes the latent single-provider reorder bug). **Manual single-server entries**: `sub add` also accepts a bare proxy URI (`vless://`/`vmess://`/`trojan://`/`ss://`/`hysteria2://`) — it becomes a `subscriptions[]` entry with `manual:true` whose `url` IS the URI: parsed locally by `parse_proxy_url` (fail-fast on a broken link, nothing saved), never fetched (`update_subscription` skips the network for it; `_merge_sub_pool` rebuilds a missing cache straight from the URI, so manual servers survive any /tmp wipe even without the subcache mirror). The legacy `subscription_url` mirror deliberately tracks the first **http(s)** sub only (`cmd_start` validates that field's scheme — a vless URI there would fail cold start); the UI onboarding gate therefore checks `subscriptions.length`, not just `subscription_url`. One-time `_migrate_subscriptions` (in `usr/bin/eclipvpn`, run at init) converts a legacy single `subscription_url` into `subscriptions[0]`. The UI (Settings ▸ Подписки) renders entirely from `/status` (which now returns `subscriptions` + keyed `subscription_meta` + `sub_id`/`sub_name` on each server) — no extra round-trip; the server list shows provider group headers only when >1 sub is active. Degenerate case: disabling/removing the LAST working sub leaves `servers.json` at its last-known pool (the count>0 swap guard protects a running tunnel) — the disabled provider's servers stay listed until a working sub exists again. **`server_filter`** (set-config key, comma-separated case-sensitive NAME substrings, e.g. `WL`) narrows the merged pool to servers whose name contains a token — applied via `_apply_server_filter` (uses `contains`, not regex) at BOTH merge points (`update_subscription` + `_merge_sub_pool`), before the `_remap_selected_server` re-pin. Use it when a provider lists hundreds of servers but only a labelled subset works on this network (probe-driven failover/auto-select otherwise burns ~15s/dead-node scanning the rest). A filter matching 0 servers is IGNORED (falls back to the unfiltered pool) so a typo can't empty `servers.json`; `set-config server_filter off|none|-` clears it and re-merges immediately.

## Files and persistence

- `/etc/eclipvpn/config.json` (chmod 600) — sole config file. `subscriptions` (array of `{id,name,url,enabled}` — the multi-provider list), `subscription_url` (legacy single URL, kept mirrored to `subscriptions[0]` for back-compat), mode, `auto_start`, `auto_mode`, `running_intent`, `device_rules`, `schedule`, `selected_server`. Always write atomically via `save_config` (validates with `jq '.'` then `mv`). `save_config` also keeps 3 rolling backups (`config.json.1..3`, newest first) — rotated only when something *other than* the volatile keys (`selected_server`, `running_intent`) changes, so failover nights don't flush the history. Recovery: `cp config.json.1 config.json && eclipvpn restart 1`.
- `/etc/eclipvpn/clash_secret` (chmod 600) — 32-hex Clash API token, lazily created by `_get_clash_secret`. Never leaves the router: clash_api binds to 127.0.0.1, and the UI gets traffic/delay data through the CGI (`traffic-poll`, `get-traffic`, `real-ping`) which uses the secret server-side.
- `/etc/eclipvpn/hwid` (chmod 600) — stable per-router UUID, lazily minted by `_get_hwid` (subscriptions.sh). Sent as `X-HWID` (+ `X-Device-OS/Ver/Model`, custom `User-Agent`) on every subscription fetch via `_sub_curl` for the panel's device-binding/HWID limit. Device-specific: deliberately excluded from `backup`/`restore` so it isn't cloned onto another router.
- `/etc/eclipvpn/build` (chmod 644) — build identity, **stamped by whatever shipped the code**, not by the running CLI: `deploy.sh`/`install-from-mac.sh` write `<short-sha> <commit-date> via=<tool>` (deploy appends `+dirty` on a worktree ship), `install.sh` writes a date-only line, the Windows installer its own. `_build_id` (in `usr/bin/eclipvpn`) reads the first line (→ `"unknown"` if absent); `system-info` exposes it as `build` and the UI shows it. `ECLIPVPN_VERSION` is a hand-set release constant and never distinguishes two deploys of the same release — `build` is what identifies the running bytes.
- `/etc/eclipvpn/subcache/` — persistent mirrors of the per-sub parse caches (`sub.<id>.servers.json`, chmod 600). `/tmp` is wiped on reboot, so `_restore_subcache` (subscriptions.sh) refills any *missing* `/tmp` copy from here (never clobbers a fresher one) — called at the top of `update_subscription`, by `cmd_start`'s cold-boot offline path, AND by `cmd_status` when `servers.json` is missing (self-heal: a no-WAN cold boot skips autostart in init.d entirely, so without this the UI showed subscriptions with zero servers until the next start/update). The mirror write is atomic (`.tmp` + `mv` + `sync`) — it's the only copy that survives a power cut. `sub remove` prunes the mirror too, or a re-added sub (same URL ⇒ same id) would briefly show stale nodes.
- `/etc/eclipvpn/state/` — persistent mirror of the failover JOURNAL (`incidents.json`, `last_switch.json`). Same contract as `subcache/`: atomic `.tmp` + `mv` + `sync`, and `_restore_state` reconciles in whichever direction is missing — mirror present + `/tmp` gone ⇒ refill `/tmp` (the reboot case); `/tmp` present + no mirror ⇒ **seed** the mirror (the upgrade case, so a journal predating this feature isn't left to die at the next reboot). Never clobbers a file that exists on either side. `/tmp` is wiped on reboot, so without this a power cut erases exactly the evidence needed to explain the outage that caused it — the 2026-08-30 emergency-failover-onto-a-RU-exit diagnosis came entirely out of these two files. Written by `_log_incident`/`_record_switch` (both best-effort: a full or read-only overlay must never abort a failover), restored by `cmd_start`, `cmd_status` and `cmd_get_incidents`. **Deliberately only these two files** — `traffic_state.json` is rewritten on every traffic poll and mirroring it would hammer the flash overlay for data that is worthless after a reboot anyway.
- `/etc/eclipvpn/{direct,vpn}_domains.txt` — user's custom domain lists (one per line).
- `/etc/eclipvpn/rules/` — cached sing-box `.srs` rule sets (`geosite-category-ru.srs`, `ru.srs`). Persisted (not in /tmp) because raw.githubusercontent.com is often blocked from inside RU: an existing cache wins over a re-download unless forced, and if there's no cache at all `_ensure_srs_present` compiles a valid *empty* `.srs` via sing-box so the VPN still starts (degraded RU routing) instead of failing.
- `/tmp/eclipvpn/` — all runtime state. Wiped on reboot. Contains `servers.json` (chmod 600, the MERGED pool from all enabled subs, each server tagged `sub_id`/`sub_name`, has VLESS UUIDs / hysteria2 passwords), per-subscription parse caches `sub.<id>.servers.json` (fetch-then-swap PER sub so one blocked panel keeps its servers), generated `xray.json`/`singbox.json`, pid files, logs (`xray.log`, `singbox.log`), `incidents.json`, `traffic_state.json`, `last_switch.json`, `last_update.json`, `subscription_meta.json` (object keyed by `sub_id`: per-provider title/quota/expiry), `op.in_progress`, `watchdog.lockdir/`, `auto_state.json`, `net_check.json` (last `net-check` verdict, cached so healthcheck/status readers can show it without re-probing).

`servers.json`, `xray.json`, `singbox.json`, and the subscription raw fetch are credential files (UUIDs / Reality private keys / Clash secret). Always `chmod 600` after writing.

## Non-obvious invariants

These are documented in inline comments at the relevant call sites — read them before touching that area. Listed here so you know they exist:

- **Watchdog is single-instance** via `mkdir $ECLIPVPN_TMP/watchdog.lockdir` (atomic on busybox; flock-based locking previously raced with init.d). Killing peers from inside `cmd_watchdog` is forbidden — traps may not be installed yet.
- **Watchdog drives log rotation, auto-recovery, and failover.** If you stop spawning it, logs grow unbounded and externally-killed VPN never revives.
- **Log writes use append-mode (`>>`)** for both daemons. Rotation does `cat tmp > file` (truncate-overwrite, preserves inode) — never `mv tmp file` (swaps inode; daemons keep writing to the unlinked old fd, lines never appear in UI).
- **`cmd_restart` is "soft"** — it preserves nftables + dnsmasq redirect across the process swap, so the LAN fails *closed* (no internet) instead of leaking direct traffic. Only `cmd_stop` does full teardown. It also has an **unchanged-config fast path**: if the freshly-generated xray/sing-box configs are byte-identical to what's running *and* the tunnel is live, it skips the swap and returns `{"status":"unchanged",...}` — but falls through to a real restart if the tunnel is dead. `restart 1` (force, always sent by the UI's Restart button, so the UI never actually sees "unchanged") bypasses this fast path; internal callers (set-mode / set-server / watchdog failover) leave it on.
- **A server switch is "make-before-break".** `cmd_restart` STAGES the new exit and verifies it BEFORE stopping the live tunnel (a warm xray on the ALTERNATE port for xray-engine targets; a throwaway `cmd_probe_server` for hysteria2, which can't be pre-warmed since sing-box *is* the exit), then ONE sing-box swap adopts it. So the **active xray SOCKS port rotates 1080↔1081**: `/tmp/eclipvpn/xray_port` holds it (absent ⇒ 1080), and the active xray config path is **`xray.<port>.json`** (NOT `xray.json`) so `stop_xray`/`is_xray_running`'s orphan sweep stays provably disjoint between the live and the staged xray. Every health/watchdog/probe that curls the tunnel uses **`_active_socks_port`** (hy2 ⇒ 1080; xray ⇒ the active port), never a hardcoded 1080. A failed stage keeps the current connection (no drop) and returns `{"error":"new server unreachable — kept current connection"}`. Helpers: `_stage_xray_port`/`_stage_exit`/`_restart_fallback`/`_kill_all_xray` (lifecycle.sh), `_active_socks_port`/`_active_xray_port` (usr/bin/eclipvpn).
- **busybox here has NO `timeout` binary either**, and `nslookup` against a blackholed resolver hangs far longer than a watchdog tick — long enough to stall the loop. `_dns_probe` (usr/bin/eclipvpn) therefore backgrounds the lookup and reaps it with the same netstat-paced busy-poll used by `start_singbox`/`stop_singbox`, killing it past the iteration cap. Don't write `timeout N ...` in router code; it silently isn't there.
- **busybox here has NO sub-second sleep** (`sleep 0.2` fails, no `usleep`). `start_singbox`/`stop_singbox`/`start_xray`/`stop_xray` therefore **busy-poll `netstat`** for the port to bind/free (the netstat call paces the loop ~20-40ms/iter) instead of `sleep 1` — sing-box binds tproxy in ~0.3s, so the old `sleep 1` loops were the entire ~5s switch gap. Don't "simplify" these back to `sleep`. The port-**bind** waits are bounded by a **30s wall-clock deadline, NOT an iteration cap**: the loop's speed swings with load, and on a cold boot sing-box needs ~10-20s to bind :2154 (CPU-starved loading `.srs` while fw4 settles) — the old ~300-iter (~10s) cap failed the bring-up and stacked init.d retries into a ~2min boot.
- **`_router_fetch` (in `usr/bin/eclipvpn`) is THE single fetch primitive for every router-originated download** — subscriptions (via `_sub_curl`), `.srs` rule-sets (`_fetch_one_srs`), blocklist/IP lists (`_rule_fetch_to`). It tries DIRECT (10s timeout) and, on failure with the tunnel up, retries through the live SOCKS exit. Rationale: the router's own traffic bypasses tproxy (mark 0x8000) and exits the raw WAN, which on some uplinks (MTS) blackholes GitHub/panel hosts that the VPN exit reaches fine — a raw `curl` in new code silently misses that fallback (that bug left blocklist + RU-direct rules dead). Always file-based (`-o`, binary-safe for `.srs`); per-call flags via `"$@"` — rule lists NEED `-L` (GitHub releases 302-redirect), subscription fetches deliberately omit it (the caller inspects a panel's redirect itself).
- **xray dials the exit by IP, not by domain** (`_resolve_server_ip` in xray.sh, resolved once at config-gen via direct resolvers Yandex 77.88.8.8 → 8.8.8.8 → keep the domain). Dial-by-domain deadlocked reconnects: a tunnel drop made xray re-resolve via 127.0.0.1 → sing-box → DoH over the DOWN tunnel, so it could never self-heal (MTS flap, 2026-06-21). SNI/Host keep the original domain, so TLS/Reality/CDN-front are unaffected. The lowest-sorted A record is picked so regeneration is DETERMINISTIC — the `cmd_restart` unchanged-config fast path and the make-before-break config compare both depend on a stable xray.json. Don't revert to dialing the domain.
- **`muted_servers` mutes a server for AUTOMATION only, and metered ≠ muted.** Comma-separated case-sensitive NAME substrings (same matcher shape as `server_filter`, but it does **not** touch the pool — `_apply_server_filter` removes servers, mute only removes them as *candidates*). A muted server stays manually selectable via `set-server`, keeps running if it is the current one, and shows a 🔇 in the UI. Motivating case: the CDN-fronted `Обход` relays are **billed per traffic**, so they must not be switched on unattended — `_is_metered_server` deliberately does NOT count them (they're a valid foreign exit), so the mute list is the only thing standing between a night of failover and a bill. Empty by default; nothing is muted unless the user says so. Three helpers in `usr/bin/eclipvpn`: `_name_has_token` (pure, glob-free — the token is quoted inside the `case` pattern so a `*` in a name can't wildcard), `_muted_tokens`, `_is_auto_skipped` (metered **or** muted). **The token list is passed INTO the matcher, never read inside it** — every caller loops the whole pool and a `get_config_val` per server means a jq spawn per server. Call sites: `cmd_auto_select`, `cmd_auto_eval`, `_watchdog_pick_best`. Mute is stored as a NAME token, never an index, because the merged pool is rebuilt on every `update` and indices shift (the same reason `_remap_selected_server` exists); one `Обход` token therefore covers every CDN relay the panel adds later, and `unmute-server` drops **every** token the name matches (else un-muting a family-muted server would visibly do nothing) and reports them in `removed_tokens`.
- **The mute is lifted by an emergency pass — but only for connectivity, never for speed.** When no un-muted server answers, `cmd_auto_select`, `cmd_auto_eval` (only if the current tunnel is actually *broken*) and the watchdog failover path re-scan the muted ones and switch anyway: no connection at all is worse than a billed one. Each logs a distinct `emergency_muted` incident so an override is visible in the journal, and `cmd_auto_select` returns `emergency:true` so the UI toast can say it. `_watchdog_pick_best`'s emergency scope is `muted_only`, NOT "try everything" — the normal pass already probed every un-muted candidate at ~13s each. **Metered stays excluded in both passes** (a Russian IP is not a working VPN — that's a correctness skip, not a cost skip). The **throughput guard deliberately does NOT get the emergency pass**: it fires on "everything is slow", and slow is not an outage — silently migrating a throttled evening onto a billed exit is exactly the surprise the mute list exists to prevent.
- **A behaviour toggle that isn't in `/status` is invisible to the user.** There are 18 whitelisted `set-config` keys; the UI can *set* two (`auto_mode`, `auto_start`) plus the mute button. `auto_failover`, `tput_guard` and `full_tunnel` are now at least *exposed* by `cmd_status`, and the UI shows an amber "Автопереключение выключено" badge (`#failoverBadge`) whenever `auto_failover === false` — strictly on an explicit `false`, so an older backend that omits the field shows no warning. Reason: turning failover off changes whether the tunnel ever self-heals, and until this existed that decision lived only in `config.json` where nothing surfaced it. When you add a behaviour key, expose it here too, and mind the boolean-default trap (`// true` is wrong for a true-default key — jq treats `false` as falsy).
- **`auto_failover` (set-config bool, default true) gates EVERY automatic change of `selected_server`** — both the connectivity-failover switch (incl. its emergency muted pass, which sits inside the same gate) AND the throughput guard's switch. Probing, re-dial, revival, and log rotation keep running when it's off (passive "Shadowrocket-like" mode: a dead server stays selected and the user switches manually); the throughput **re-dial** also stays, since it re-opens a flow to the SAME server and changes no selection. The throughput switch was gated only by `tput_guard` until 2026-08-30 — a user who turned failover off to stop surprise switches still got them from that path. When it's off, bail BEFORE the benchmark: probing the pool costs ~13s/server and the result can't be acted on.
- **The emergency muted pass ranks by pure latency, so the NEAREST server wins — and from inside RU that is systematically a Russian exit.** Observed 2026-08-30 on the live router: the tunnel dropped, no un-muted candidate answered, and failover landed on a server whose exit IP geolocated to Selectel RU — a "working" tunnel with no VPN at all, until the user noticed and switched back manually 65s later. Two things conspire: (1) `_is_metered_server` matches **carrier names** (МТС/Билайн/Мегафон/Tele2), so a RU-hosted node named `Россия (прямой)` or `Россия · Beget` is not classified metered and the correctness guard never fires; (2) name matching fundamentally can't separate `Россия (прямой)` (RU exit) from `Россия → Финляндия` (RU entry, FI exit) — so don't "fix" this by widening the matcher to the 🇷🇺 flag or the word `Россия`, it would exclude the good server too. A real fix has to classify by MEASURED exit country (`cmd_probe_server` already returns the exit IP), not by name. Separately, `_watchdog_pick_best` ABORTS the candidate scan when 2 consecutive probes fail and a WAN re-check says the uplink itself is down — no server switch fixes a dead WAN, and probing ~20 nodes burns ~13s each.
- **A `vpn` device rule needs a singbox regen, not just nft.** `direct` device rules are an nftables tproxy bypass; `vpn` rules (force a device through the tunnel even toward geoip-ru destinations, e.g. a Hik-Connect camera whose P2P node geo-resolves as RU) are sing-box `source_ip_cidr` route rules that only exist in a regenerated singbox.json. `_apply_device_rules` (config.sh) rebuilds nft AND soft-`cmd_restart`s so both take effect immediately — the old nft-only path left `vpn` rules inert until a manual restart.
- **`op.in_progress` sentinel** is set during user-initiated lifecycle ops. Watchdog defers revival while it's held; otherwise watchdog races `cmd_restart`'s `stop_xray` window and spawns a parallel xray fighting for port 1080.
- **`running_intent` (in config) ≠ `auto_start`.** `auto_start` is only consulted at boot; `running_intent` tells watchdog whether to revive after an external kill.
- **`pgrep -f 'eclipvpn watchdog'` matches itself.** `_ensure_watchdog` uses the `[/]usr/...` character-class trick to self-exclude — don't "simplify" it.
- **xray ≥ 26.4.17 required** — opkg ships 25.1.30 which has broken XHTTP+Reality. `install.sh` downloads the right binary by arch.
- **curl/libcurl version skew self-heals in the installers.** The RouteRich opkg feed once upgraded `curl` (8.19) without `libcurl4` (8.12) — curl died at load (`Error relocating … symbol not found`) and EVERY fetch failed silently (subscriptions parsed to 0 servers). `install.sh`/`install-from-mac.sh` name `libcurl4` explicitly (opkg only) and verify by actually RUNNING `curl --version` (`command -v` passes even when the binary can't load), force-reinstalling both on failure.
- **All JSON construction goes through jq.** Values from subscriptions (parse.sh), domain lists (rules.sh/singbox.sh), and HTTP requests (cgi-bin) are user/upstream-controlled. String-concatenated JSON broke or got injected at least once per file in history.
- **Logging — `flog` / `_err` / `flogd`** (defined in `usr/bin/eclipvpn`). `flog "msg"` → syslog (tag `eclipvpn`, read via `logread` or `get-log`). **`_err "msg"`** logs `ERROR: msg` AND emits `{"error":"msg"}` — use it for EVERY user-visible error return so a failure is never silent in the log (the recurring "ошибка есть, в логах пусто"). **`flogd "msg"`** is a DEBUG trace, OFF by default, gated on the `log_debug` config key — `set-config log_debug true` turns it on without a redeploy (used to step-trace the make-before-break switch). sing-box's own log level is the `singbox_loglevel` config key (default `info` — drives the UI "Журнал" flow panel, which reads singbox.log `outbound/`/`dns:` lines; `warn` shrinks the raw log but empties the Все/VPN/Direct/DNS tabs). The "Ошибки"/error filter in `cmd_get_log` includes EclipVPN's own `ERROR` syslog lines (from `_err`), not just sing-box/xray.
- **CGI input validation at the boundary** in `www/cgi-bin/eclipvpn` uses `case` patterns, not regex. Every parameter forwarded as a CLI arg is validated; POST bodies for `set-config` and `restore` are passed via stdin (avoids argv injection).
- **CGI has an anti-CSRF / anti-rebinding gate** (top of `www/cgi-bin/eclipvpn`, before the dispatch `case`). Two checks: (1) a `Host` allow-list — only IP literals / loopback / bare-hostname / `*.lan` pass; a dotted name with letters (a real public domain) is rejected, which kills DNS-rebinding; (2) every **state-changing** action requires a same-host `Origin` *or* `Referer` — a cross-site `fetch` sends a foreign Origin, a cross-site `<img>`/`<form>` a foreign (or, under `no-referrer`, absent) Referer, all rejected. This rides on Origin/Referer specifically because **uhttpd only forwards a fixed header allow-list to CGI** (`Accept/Host/Origin/Referer/User-Agent`) and *drops custom headers* — an `X-Requested-With`-style marker never reaches the script, so don't add a gate that depends on one. The exempt read-only set is the `status|ping|real-ping|healthcheck|diagnose|system-info|backup|traffic-poll|net-check|get-*` arm of that `case`; a **new mutating action must NOT match it**, or it ships unprotected. The UI relies on the browser sending a same-origin `Referer` automatically — don't add a `no-referrer` meta/policy to `index.html` or every write self-blocks. Without this gate, a drive-by page on the LAN could repoint `subscription_url` via one GET → full traffic MITM.
- **`save_config` is the *only* writer of config.json.** It validates JSON with `jq '.'` before `mv`-ing. Bypassing it has lost subscriptions to corrupt writes.
- **Boolean keys in config are stored as JSON `true`/`false`**, not strings. `auto_start` defaults via the explicit `if . == false then false else true end` pattern in `cmd_status` — `// true` is wrong here because jq's `//` treats `false` as falsy.
- **DNS-direct goes to Yandex 77.88.8.8 (UDP), not Cloudflare 1.1.1.1.** Cloudflare returns SERVFAIL for VTB and a few other RU bank domains — their authoritative NS refuse foreign resolvers. Yandex resolves everything and returns nearby RU CDN endpoints. Don't "modernize" this back to Cloudflare. Under CGNAT that hijacks UDP/53 (e.g. SevenSky), direct resolution can break — RU sites then go via VPN.
- **`dns_direct_servers` is an ordered fallback list, and the watchdog picks from it.** `dns-direct` is ONE resolver in the generated config, so when it stops answering every direct-path lookup dies with it — under a UDP/53-hijacking CGNAT that means all RU sites go dark while the tunnel looks perfectly healthy (nothing else notices: the connectivity probe goes *through* the tunnel). The guard in `cmd_watchdog` probes the active resolver every `DNS_EVERY` (15) ticks and, after `DNS_FAIL_MAX` (2) consecutive misses **and** a WAN re-check, promotes the first entry that answers into `$ECLIPVPN_TMP/dns_direct_active`, logs a `dns_failover` incident and soft-restarts to regenerate. Deliberately conservative — the fix costs a tunnel bounce. There is **no auto-failback**: the choice lives in `/tmp`, so a reboot returns to the primary instead of flapping on every recovery. `_active_dns_direct` honours the saved pick ONLY while it is still a member of the configured list, so editing the key takes effect immediately instead of waiting for the next failover. Default (empty key) is `77.88.8.8,77.88.8.1` — both Yandex, for the SERVFAIL reason above.
- **`dns_overrides` pins a domain family to one resolver, ahead of every other DNS rule.** `"domain=ip"` pairs, comma separated (e.g. `vtb.ru=77.88.8.8`) — the generalisation of the global Yandex hardcode, so the next bank that refuses foreign resolvers is a config line, not a code change. The generator groups pairs BY RESOLVER through jq's `group_by`, and sorts the domains inside each group with `unique`: the emitted JSON is identical for any ordering of the config string, which the `cmd_restart` unchanged-config fast path depends on (before `unique`, reordering the pairs produced different bytes and forced a pointless bounce — locked in by `tests/test_dns.sh`). Override rules are prepended (`$dns_ov_rules + $dns_rules`) because an explicit user pin must outrank the force-VPN / `geosite-ru` / final rules the mode builders emit.
- **QUIC (UDP 443) reject sits *before* the force-VPN match** in the nft chain. Intentional: QUIC over Reality+XHTTP is unstable, so we want Gemini / ChatGPT etc. to fall back to TCP rather than tunnel QUIC. If you reorder force-VPN above the QUIC reject, AI services will try QUIC through the VPN and break.
- **WAN MTU is capped to 1400 on start** (`_apply_wan_mtu` in network.sh, restored on stop via `/tmp/eclipvpn/wan_mtu.orig`). Some wired CGNAT uplinks silently drop >1400-byte DF packets *and* the ICMP frag-needed replies (PMTU black hole) — the VPN handshake works but the tunnel stalls. Route-level MTU, nft MSS clamping, and xray `tcpMaxSeg` were all tried and do **not** fix it; only the interface cap does. Tunable via config `wan_mtu` (0 = leave the interface alone).
- **IPv6 is killed, not tunnelled.** The whole tproxy/route/DNS stack is IPv4-only, so on a dual-stack WAN a LAN client would reach v6 destinations straight out the WAN — past the tunnel (real-IP + DNS leak) and past the QUIC/DoT rejects. `_ipv6_killswitch_on` (network.sh) therefore fails **closed**: it writes `1` to the LAN bridge's `disable_ipv6`, saving the prior value in `/tmp/eclipvpn/ipv6_disable.{saved,iface}` (in /tmp so a power-yank can't strand IPv6 off). Soft `cmd_restart` keeps the switch across the process swap; only `cmd_stop` restores it. If you ever add v6 tunnelling, this is what has to go first.
- **`_sync_zapret_exclude` (usr/bin/eclipvpn) mirrors the VPN server IPs into zapret's user-exclude list** (`/opt/zapret/ipset/zapret-ip-user-exclude.txt`, then restarts zapret). If the router also runs zapret, its NFQUEUE postrouting hook fragments xray's ClientHello to the exit and the Reality handshake fails outright. No-op when `/opt/zapret` is absent, and it skips the write+restart when the list is unchanged so cron-driven `update` doesn't churn zapret every night. Called from `cmd_update` (servers.sh) — a new code path that rewrites `servers.json` should call it too.
- **`_vpn_live` vs `_vpn_running`.** `_vpn_running` keys off the *selected* server's engine (hysteria2 ⇒ sing-box only, else xray+sing-box). Right after `selected_server` may have changed (`cmd_set_server`, `cmd_auto_select`), use **`_vpn_live`** (`is_singbox_running || is_xray_running`) to decide "is a tunnel up, should I restart" — otherwise switching off a live hysteria2 server onto an xray one evaluates `is_xray_running` (false) and the switch silently no-ops or collides.
- **Watchdog throughput guard**: latency probes only prove the server *answers* — a peak-overloaded exit pings fast while shaped to a crawl. Every `TPUT_EVERY` ticks the watchdog measures real tunnel speed through SOCKS; after `TPUT_SLOW_MAX` consecutive readings under `tput_min_kbps` (default 500) it acts in two stages: (1) **re-dial** — the policer pins flows per-TCP-connection, so it first measures a fresh flow to the *same* server via throwaway xray and, if clearly fast, does `cmd_restart 1` in place (one attempt per incident); (2) **switch** — benchmarks all servers by *measured throughput* and switches only if the best candidate clears the threshold and is >2× faster. The cooldown is adaptive: it gates only while the last switch/benchmark has produced no good reading since (`tput_switch_helped=0`, the "every server is throttled" peak) — a switch that restored speed and later got re-squeezed (rolling TSPU waves, observed 2026-06-10) may act again as soon as the low reads re-accumulate (~7 min). After a *flopped* action (squeezed before any good reading) the first re-action is allowed after `TPUT_COOLDOWN_FAST` (5 min), the second waits the full `TPUT_COOLDOWN` (20 min) — a flop with a free server available was observed 2026-06-12, don't "simplify" any of this back to an unconditional cooldown. Config keys: `tput_guard` (default true), `tput_min_kbps`.
- **Boot gates in init.d**: waits up to 60s for WAN (slow CGNAT) and up to 20s for NTP clock sync before starting. Reality handshakes fail with a wrong clock, so don't remove the date check.
- **`set-config` keys are whitelisted** in `cmd_set_config` (`usr/lib/eclipvpn/config.sh`), with per-key value validation. Adding a new tunable means adding it to both the key whitelist and the matching validation branch.
- **Cron markers are anchored.** Schedule lines end in `#eclipvpn`, auto-update in `#eclipvpn-update`, watchdog supervision in `#eclipvpn-watch`; `_remove_cron` greps `#eclipvpn$` (anchored) — an unanchored match once deleted the auto-update line on every schedule change. `_ensure_cron_state` (called from cmd_start and cmd_restore) reconciles crontab with config — that's what re-arms schedule/auto-update after `restore` or migration; don't add ad-hoc crontab writes elsewhere.
- **The watchdog is itself supervised** by a `*/5` cron line (`ensure-watchdog`, marker `#eclipvpn-watch`, installed unconditionally by `_ensure_cron_state`). The command self-gates on `running_intent`, so after `cmd_stop`/init.d stop a dead watchdog stays dead. Without this, an OOM-killed watchdog silently lost failover and log rotation until the next manual start.
- **Subscription and rule updates are fetch-then-swap.** `update_subscription` commits servers.json only when ≥1 server parsed (a 0-server parse once wiped the live list); `refresh_rules` (rules.sh) fetches into `rules.new` and swaps only after a sanity check, carrying forward optional lists the new fetch missed. Don't reintroduce `rm -rf rules` before a fetch.
- **Watchdog failover re-arms**: the switch scan fires at `max_fails` and then every 15 ticks while the outage persists (`(fail_count - max_fails) % 15`). `_watchdog_pick_best` does 2 spawn-and-probe attempts per candidate (cold XHTTP+Reality flakes ~50% on first request) and uses probe ports 1182+ — disjoint from `cmd_probe_server`'s 1082+ range, which is deliberate.
- **`deploy.sh` ships COMMITTED bytes (`git archive HEAD`), not the working tree.** This repo lives inside a Yandex.Disk sync folder; tarring the working tree once shipped a half-synced (truncated) `rules.sh` and the tunnel never came up (2026-06-16). The archive reads the immutable object store, so a mid-sync file can never reach the router. Consequence for any edit-then-deploy loop: **commit first**, or the deploy hard-fails with "uncommitted changes under usr/ www/ etc/." — `ALLOW_DIRTY=1` is the escape hatch and it re-opens the corruption race (the build stamp gets `+dirty`). The dirty check is scoped to *tracked* modifications (`--untracked-files=no`) so Yandex.Disk conflict-copies don't block a clean deploy.
- **Only single-digit file descriptors in shell redirections.** CI's `sh -n` is **dash**, which parses only fds 0-9; busybox ash and macOS `sh` accept `) 200>lock` fine, so a multi-digit fd passes every local check and fails CI silently-ish (2026-07-23). The `flock` subshells in `servers.sh`/`traffic.sh` use `9>` for this reason — don't "restore" the conventional 200.
- **Clash API on `:9090` is LAN-exposed.** Token is created lazily, persisted to `/etc/eclipvpn/clash_secret`, and handed to the UI through `/status`. Threat model is "trust the home LAN" — anyone on the same Wi-Fi can read traffic stats / switch proxies. Don't deploy this to a public Wi-Fi router without rethinking that.

## Adding a new command

1. Add `cmd_foo()` in the matching domain lib under `usr/lib/eclipvpn/` (lifecycle/servers/domains/traffic/health/config/watchdog) — or in `usr/bin/eclipvpn` itself only if it's core/shared infra. If you create a NEW lib file, add it to the `. "$ECLIPVPN_LIB/*.sh"` block in `usr/bin/eclipvpn` **and** add ONE line to `packaging/ship-files` — the single ship manifest read by `deploy.sh`, `install.sh`, `install-from-mac.sh`, and `windows-installer/eclip-core.ps1`. No installer's file list needs editing anymore (they all read the manifest). The CI `manifest-guard` job fails the build if a `usr/lib/eclipvpn/*.sh` is missing from the manifest. `packaging/ship-files` is dev-only — it is NOT shipped to the router (like `tests/`).
2. Wire the dispatch case at the bottom of `usr/bin/eclipvpn` (`foo) cmd_foo "$2" ;;`).
3. Wire `www/cgi-bin/eclipvpn` to forward the action (and validate any new parameters in the boundary block).
4. Add fetch + render in `www/eclipvpn/index.html` (`API='/cgi-bin/eclipvpn'`, polled actions in `loadStatus`/`loadDomains`/etc).
5. Run `./deploy.sh` to ship.

## Windows installer (`windows-installer/`)

A self-contained, **fully offline** Windows `.exe` that installs EclipVPN onto a router over SSH — for end users who can't run `install.sh` on the router (GitHub is blocked in RU; dropbear has no sftp). This is the one part of the repo with a real build step. See `windows-installer/README.md` for the full picture; the load-bearing facts:

- **Layered design**: `eclip-core.ps1` (install engine over SSH.NET, mirrors `install-from-mac.sh`) ← `install-eclipvpn-gui.ps1` (WPF GUI: dark card, EN/RU, router auto-detect, colored log) / `install-eclipvpn.ps1` (headless CLI) ← `launcher.cs` (C# self-extract stub carrying `bundle.zip`, compiled by `build-exe.ps1` with the framework `csc.exe`, **not** ps2exe).
- **What's committed vs. generated**: sources (`.ps1`, `.cs`, `lang.ru.txt`, `README.md`) are tracked. The `.exe`, `bundle.zip`, `eclip.ico`, `payload/bin/<arch>/*` static binaries (xray/sing-box/jq/curl/ca, currently **aarch64 only**), and `lib/Renci.SshNet.dll` are gitignored — regenerate per the README before a build.
- **`build-exe.ps1` stages the router source straight from the working tree** (`usr/`/`www/`/`etc/`), so a rebuild always ships current code — rebuild after any change under those dirs.
- **Rebuilding the `.exe` is a 4-step release ritual, not one command.** The installer's SHA-256 is published in two tracked files, so after `build-exe.ps1`: (1) `Get-FileHash … -Algorithm SHA256`, (2) update the hash in `README.md` ("SHA-256:" line) **and** `docs/eclipvpn_manual.tex`, (3) rebuild the PDF (`tectonic eclipvpn_manual.tex`), (4) upload the `.exe` to the GitHub release. Skipping (2)/(3) leaves users verifying against a stale hash. Note the build must run on Windows (framework `csc.exe`), so this lands as a separate commit from router-code work done on the Mac.
- **Gotchas that bite**: keep every `.ps1` **pure ASCII** (PS 5.1 reads a BOM-less script as the ANSI codepage; localized text lives in `lang.ru.txt`, read as UTF-8 data). dropbear aborts an SSH exec >~10-16 KB, so files are pushed in ~7.5 KB base64 chunks. The C# stub detects zip dir entries by empty `entry.Name` (.NET writes `\` separators, so `EndsWith("/")` fails). `ECLIP_GUI_SMOKE=1` builds the window and auto-closes for a headless check.
